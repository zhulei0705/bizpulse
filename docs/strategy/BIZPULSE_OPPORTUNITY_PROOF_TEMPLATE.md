# BIZ-V3-01 商机证明书模板

日期：2026-10-09。用途：给特定付费客户审阅的真实商业需求核验材料。空白模板，未确认真实商机、联系人或客户反馈。无需数据库写入。

证明书编号、版本、制作人、人工审核人/日期、对应客户与能力档案版本、核验基准时间及时区：待填写。客户商业秘密与目标公开资料分开存放，仅向授权者交付。

## 一、先给结论

推荐结论：待核验。允许选“建议跟进 / 先核实 / 不推荐跟进 / 历史研究”。需求等级：UNKNOWN；技术/能力匹配：UNKNOWN；资格：UNKNOWN；商业完全匹配：未确认；是否客户已知：待客户判断。不能以空模板默认为推荐。

D3=明确有证据需求；D2=强变化但具体需求待核实；D1=假设；D0=缺可靠需求证据。等级和当前有效性分别展示；历史 D3 不进当前机会队列。

## 二、14项交付字段

|序号|字段|待填写内容与最低要求|
|---|---|---|
|1|目标企业及真实主体|企业/采购方全称、业务角色、主体依据；匿名/关联不明 UNKNOWN，不能以代理当采购方|
|2|明确商业事件|原文事件、项目/标包、需求对象、发生时间；普通招聘不写成购买服务需求|
|3|需求真实性等级|D0–D3及逐项来源/日期/主体/状态/相关性/完整性依据；LLM分数不能代替|
|4|原始证据及来源|需求原URL/最终URL、官方/客户来源、采集或获授权时间、发布时间、版本/哈希、准确摘录位置|
|5|为什么适合该客户|对应客户能力档案条目、产品/服务配置、条件、双边引用；推断标 INFERENCE|
|6|符合条件|逐项需求值、能力值、单位/工况、操作符、转换和结果|
|7|不符合条件|明确硬性不符和证据；软性偏差分开；无不符证据不写“全部满足”|
|8|尚待核实条件|技术/资格、需求范围、报名、地域、交期、预算等 UNKNOWN，给具体核实问题|
|9|潜在商业价值|原预算及口径或客户价值假设；预算/中标金额/预测分开；没有依据保持 UNKNOWN，不给虚构成交概率|
|10|截止与生命周期|公告日、核验日、报名期、截止/时区、意向/开放/澄清/结束/中标/取消/未知、最新更正；无截止写 UNKNOWN|
|11|真实公开联系渠道|官网联系页/业务表单/公开业务电话邮箱及来源、核验日期、用途；不编联系人、不猜邮箱、不把渠道当营销授权|
|12|下一步行动|建议由谁核实什么、通过什么已核验渠道、何时；本文件不发送消息|
|13|风险说明|来源/状态/主体/参数/资格/保密/客户已知/重复等；严重错误隔离停批|
|14|客户反馈|未审阅/有效/无效/不能判断、原因及原话位置；已知/愿跟进独立字段，实际动作与日期；无回复不填认可|

关键 FAIL → 不推荐；UNKNOWN → 先核实，不能完全匹配。仅全部适用硬门槛 PASS 后比较价值、适配、时效、获客成本、联系渠道和当前交付资源。D3及门槛通过才能成为“内部核验有效候选”；仍须人工审阅和客户实际评判。客户确认有效、愿跟进、实际跟进与付款分别统计。

技术 MATCH 不等于具备投标资格；D2不得当明确采购；历史中标/结束/取消不得建议当前投标。若无可核验渠道可建议先补渠道，但不虚构有联系人。客户已知不改变事实，但应标识增量价值不足及重复处理。

## 五、重复与负结果

去重口径：同一客户+同一真实主体/项目标包+同一商业事件。澄清/延期有实质改变时附在原卡版本，非新机会；新独立项目须说明区别。研究发现重复但未交付不计卡片交付量。客户提供的已知清单版本与日期：待填写。

允许整批交付“没有值得推荐的机会”：已审来源和范围、真实候选数、排除/未知原因、覆盖缺口、截至时间、是否建议继续及下一核实问题。没有有效候选不补历史公告，不隐去未解析附件。费用与退出依据事先签署范围，而非把零结果称商业成功。
